# CN-058-9-2 課題仕様書

## 1. 目的・学習内容

- **【目的】:** `Promise` / `async/await` を用いて非同期通信を連鎖させ、別アプリ（受注明細）への一括登録後に採番されたレコードIDを取得し、親アプリ（受注管理）のサブテーブル（フィールドコード: `受注明細Table`）に書き戻して更新（PUT）できるようになること。

---

## 2. 使用アプリ

9-1で作成したアプリを引き続き利用すること。

- **11** 【入社前研修】受注管理
- **12** 【入社前研修】受注明細
- **13** 【入社前研修】顧客マスタ
- **14** 【入社前研修】商品マスタ

---

## 3. 機能要件

### ■ 要件①: レコード登録 ＆ 受注明細番号の保存
受注管理アプリの値を受注明細アプリにレコード登録し、発行された `受注明細番号` を受注管理アプリのサブテーブル（`受注明細Table`）に保存する。

1. **ボタンの設置:**
   - 詳細画面ヘッダースペースに **「テーブル展開#2」** ボタンを設置する。
2. **実行条件:**
   - 上記ボタンがクリックされたときにテーブル展開を実行。
   - 受注明細アプリにレコード新規作成後、受注管理アプリのサブテーブル（`受注明細Table`）に受注明細番号（レコード番号）を保存する。
3. **コピー対象フィールド（受注管理アプリ → 受注明細アプリ）:**
  - `受注管理No` -> `受注番号`
  - `受注日` -> `受注日`
  - `顧客コード` -> `顧客コード`
  - `数量` -> `数量`
  - `小計` -> `小計`
  - 商品マスタ項目およびテーブル内項目：
    - `商品コード` -> `商品コード_0`
    - `カテゴリ` -> `カテゴリ` （※2026-08-05 追加要件）
    - `商品名` -> `商品名` （※2026-08-05 追加要件）
    - `販売単価` -> `単価` （※2026-08-05 追加要件）

### ■ 要件① 実装詳細

1. **ボタン設置:**
   - `kintone.app.record.getHeaderMenuSpaceElement()` を用いてボタンを設置する。
   - 設置したボタンにクリックイベントを設定する。  
   *(※ JavaScript、jQuery のどちらを使用しても可)*
2. **テーブル展開処理手順:**
   - `event.record` を用いてレコードの情報を取得する。
   - 各レコード内のサブテーブル（`受注明細Table`）の値を取得する。
   - 取得したテーブル各行から受注明細アプリに登録する値を取り出し、登録用パラメータを作成する。
   - `/k/v1/records.json` (POST) を用いて受注明細アプリにレコードを新規作成する。
   - レスポンスから受注明細アプリの `受注明細番号`（レコード番号）を取得する。
   - 取得した値を用いて受注管理アプリ更新用パラメータを作成する。
   - `/k/v1/record.json` (PUT) を用いて受注管理アプリのレコードを更新する。

## 4. 設計仕様 & 制約事項

> [!IMPORTANT]
> **学習要件:**  
> 学習のため、`@kintone/rest-api-client` は**使用せず**に実装してください。

- **片方向連携:** コピーの方向は「受注app → 明細app」への片方向とする。
- **重複登録:** 本課題では、更新処理への対応は不要。明細アプリに重複登録されて可。
- **設計の注意点:** 受注明細番号にレコード番号を用いているが、実務においてアプリ移行時等の問題が発生するため、ユニークキーにレコード番号を使用することはない。

## 6. 模範解答コード (JavaScript / async/await 版)

```javascript
/**
 * 課題名: CN-058-9-2 明細登録 ＆ 明細番号（採番ID）の親テーブル反映
 * 対象アプリ: 【入社前研修】受注管理 (AppID: 11)
 */
(function() {
  'use strict';

  // 転送先「受注明細」アプリのID
  const DETAIL_APP_ID = 12;

  /**
   * レコード詳細画面が表示されたときに実行されるイベントハンドラ。
   * 詳細画面に「テーブル展開#2」ボタンを設置します。
   * 
   * @param {Object} event kintoneのイベントオブジェクト
   * @returns {Object} イベントオブジェクト
   */
  kintone.events.on('app.record.detail.show', function(event) {
    const record = event.record;

    const headerMenuEl = kintone.app.record.getHeaderMenuSpaceElement();
    if (!headerMenuEl || document.getElementById('btn_table_expand_2')) {
      return event;
    }

    const btn = document.createElement('button');
    btn.id = 'btn_table_expand_2';
    btn.innerText = 'テーブル展開#2';
    btn.className = 'kintoneplugin-button-normal';
    btn.style.margin = '10px';

    /**
     * ボタンがクリックされたときに実行される非同期処理。
     * サブテーブルのデータを取得し、受注明細アプリへの一括登録(POST)後、
     * 発行されたID群を親レコードのサブテーブルへ書き戻し更新(PUT)します。
     * 
     * @returns {Promise<void>}
     */
    btn.addEventListener('click', async function() {
      const subtable = record.受注明細Table ? record.受注明細Table.value : [];
      if (!subtable || subtable.length === 0) {
        alert('展開対象の明細行が存在しません。');
        return;
      }

      /**
       * サブテーブル of 各行から受注明細アプリ用の登録データを生成するコールバック関数。
       * 
       * @param {Object} row サブテーブルの1行分のデータ
       * @returns {Object} 登録用レコードオブジェクト
       */
      const recordsToPost = subtable.map(function(row) {
        return {
          '受注番号': { value: record.受注管理No.value },
          '受注日': { value: record.受注日.value },
          '顧客コード': { value: record.顧客コード.value },
          '商品コード_0': { value: row.value.商品コード.value },
          'カテゴリ': { value: row.value.カテゴリ.value }, // 2026-08-05 追加要件
          '商品名': { value: row.value.商品名.value },     // 2026-08-05 追加要件
          '単価': { value: row.value.販売単価.value },     // 2026-08-05 追加要件
          '数量': { value: row.value.数量.value },
          '小計': { value: row.value.小計.value }
        };
      });

      try {
        // Step 1: 明細アプリに新規一括登録 (POST) を待機
        const resp = await kintone.api(
          kintone.api.url('/k/v1/records.json', true),
          'POST',
          { app: DETAIL_APP_ID, records: recordsToPost }
        );

        // 返却された明細レコードID群 (例: [101, 102])
        const postedIds = resp.ids;

        /**
         * 登録された明細レコードのIDを、対応するサブテーブル行の「受注明細番号」へ反映するコールバック関数。
         * 
         * @param {Object} row サブテーブルの1行分のデータ
         * @param {number} index インデックス番号
         * @returns {Object} 更新用サブテーブル行オブジェクト
         */
        const updatedTable = subtable.map(function(row, index) {
          return {
            id: row.id, // サブテーブル既存行の内部IDを維持
            value: Object.assign({}, row.value, {
              '受注明細番号': { value: String(postedIds[index]) }
            })
          };
        });

        // Step 3: 受注管理アプリ自体のレコードをPUT更新
        await kintone.api(
          kintone.api.url('/k/v1/record.json', true),
          'PUT',
          {
            app: kintone.app.getId(),
            id: kintone.app.record.getId(),
            record: { '受注明細Table': { value: updatedTable } }
          }
        );

        alert('受注明細の登録および受注明細番号の書き戻しが完了しました。');
        location.reload(); // 最新表示のために画面リロード
      } catch (err) {
        console.error('エラー発生:', err);
        alert('処理中にエラーが発生しました: ' + (err.message || JSON.stringify(err)));
      }
    });

    headerMenuEl.appendChild(btn);
    return event;
  });
})();
```

## 7. コードの解説

1. **非同期処理の順序保証 (`await`)**
   - 明細アプリへの POST が成功した後に返ってくる `resp.ids` を使用するため、`await kintone.api(...)` で確実に通信の完了を待ちます。
2. **サブテーブル行の内部 ID (`row.id`) の維持**
   - `updatedTable` を生成する際、各行の `id: row.id` を引き継ぐことで、既存のサブテーブル行を削除せずに「受注明細番号」だけを上書きできます。
3. **親レコードの更新 (`/k/v1/record.json` PUT)**
   - 全行の割り当てが終わった後、現在開いている受注管理レコード（`kintone.app.record.getId()`）を更新し、`location.reload()` で画面を更新します。
