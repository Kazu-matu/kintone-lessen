## 1. システム概要 & 設計目的

### 1.1. システムの目的
本アプリ（`15【入社前研修】予実管理`）は、拠点や年度ごとの**予算**と**実績**を一元管理し、進捗状況や差異、達成率をビジュアルかつ簡潔に可視化することを目的としたkintoneアプリケーションです。

### 1.2. 設計上の特徴
- **数値の精度と丸め設定:** 小数点以下の精度を `16` 桁、表示スケールを `4` 桁に設定し、丸めモードは `HALF_EVEN`（偶数への丸め、銀行丸め）を採用しています。これにより正確な予実計算が担保されます。
- **カスタマイズビューの採用:** 標準の一覧表示形式に加え、HTML/CSS（Materialize）およびJavaScriptで生成したカスタムテーブルを表示する「予算達成率」ビューを搭載しています。

## 5. 追加実装するカスタマイズ仕様

標準機能（フォーム定義・標準一覧）とは別に、**開発者が外部ファイルを通じて「追加で実装（アップロード）する箇所」**です。

### 5.1. CSSカスタマイズの追加（外部CDNインポート）
Materialize CSS をアプリに適用するために、以下のURLを設定画面の「PC用CSSファイル」に追加します。

```text
https://cdnjs.cloudflare.com/ajax/libs/materialize/1.0.0/css/materialize.min.css
```

### 5.2. JavaScriptカスタマイズの追加（ファイルアップロード）
カスタマイズビュー `<div id="customize"></div>` 内に、計算結果を伴ったMaterializeテーブルを動的に描画するロジックを実装します。

#### ① イベントハンドラの実装
- 対象イベント: `app.record.index.show`
- 実行前ガード:
  - 画面上に `div#customize` が存在しない場合は処理を中断。
  - 現在の `event.viewName` が `'予算達成率'` でない場合は処理を中断。

#### ② 動的計算ロジックの実装
各レコード行をレンダリングする際、JavaScript側で以下の動的計算を行います。

- **差異の算出:**
  - 計算式: `実績 - 予算`
  - 表示形式: `toLocaleString()` により3桁カンマ区切りにし、正数の場合は先頭に `+` を付与。末尾に「 円」を追加。
- **達成率の算出 (ゼロ除算防止ガード付き):**
  - 計算式: `(実績 / 予算) * 100` (%)
  - **ガードロジック:** 予算が未入力、または `0` の場合は計算をスキップし、達成率を `0.00 %` とします。
  - **切り捨て処理:** 小数点第3位以下を切り捨てるため、`Math.floor(達成率 * 100) / 100` を適用します。

#### ③ セキュリティ (XSS) 対策の実装
ユーザーが入力した文字列型データ（`予算No`, `年度`, `拠点`）を出力する際は、HTMLタグがそのまま実行されないよう、以下のエスケープ関数を必ず通して結合します。
```javascript
function escapeHtml(str) {
  if (!str) return '';
  return String(str)
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#39;');
}
```

#### ④ Materialize CSS クラスの動的適用
生成するHTMLコード内に以下のクラスを動的に埋め込みます。

- **テーブル全体:** `<table class="striped responsive-table highlight">`
- **100%未満時の達成率セル:**  
  達成率が 100% 未満と判定されたセルの `<td>` タグに対し、以下のMaterializeカラークラスを追加します。
  - 背景色: `red lighten-5`
  - 文字色: `red-text text-accent-4`

## 6. チーム開発・保守運用ガイドライン

本アプリを複数人の開発チームで安定的かつ効率的に保守していくための標準ルールです。

### 6.1. CSSフレームワーク依存の局所化
カスタマイズビューの HTML 構築時に外部の CSS クラス（Materialize）を JavaScript 内にベタ書きしていますが、将来的なデザイン刷新や他フレームワークへの移行時に、JavaScriptを書き直す範囲が広がってしまいます。
- **専門家のアドバイス:**  
  レイアウト構築（`<table>`, `<tr>`, `<td>`）は標準のセマンティックな HTML をベースにし、達成率100%未満のセルのように「状態（State）」を示すスタイルクラスを付与する設計に留めます。Materialize 固有のクラス（`red lighten-5` 等）はなるべく JavaScript に直接記述せず、以下のように状態を示すセマンティックなクラス名（例: `is-warning`）を付与し、アプリ個別CSSファイル側で実際の Materialize カラークラスを割り当てるように疎結合にすると、保守性が大幅に向上します。
  ```javascript
  // 改善前
  let rateClass = ratePercent < 100 ? 'red lighten-5 red-text text-accent-4' : '';
  
  // 改善後 (HTMLとスタイル状態の関心の分離)
  let rateClass = ratePercent < 100 ? 'is-warning' : '';
  ```

### 6.2. ページネーションとDOMライフサイクルの理解
本アプリは一覧画面に「ページネーション（改ページ）」を表示する設定になっています。ページ切り替え時、ブラウザはページ全体を再読み込みするのではなく、kintone内部でDOM要素（`div#customize`）の中身のみをクリアして再描画（部分書き換え）します。
- **専門家のアドバイス:**  
  改ページや並び替えの度に `app.record.index.show` イベントが再実行されることを意識してください。イベント内でグローバルなDOM要素にリスナー（`addEventListener`）を重複して登録してしまわないよう、必ずイベント空間内で完結する設計にするか、対象DOMのクリーンアップ処理（初期化）を行ってください。

### 6.3. CDNリソースのバージョンロック
外部のMaterialize CSS (CDN)を読み込む際は、指定されたURLに必ず明示的なバージョンを指定（本仕様書では `1.0.0`）し、バージョン未指定の `@latest` リンクは使用しないでください。
- **専門家のアドバイス:**  
  予告なくCDNのライブラリのバージョンが上がると、テーブル表示が突然乱れるなどの本番障害につながります。バージョンロックによる「再現性」の担保は、チーム開発でのリリース基準として徹底する必要があります。
